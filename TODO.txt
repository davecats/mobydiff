Open items (reviewed 2026-09-26)
================================

Items from the 2026-05 lists that are DONE and were removed: parallel HDF5 on the
NVHPC stack and production I/O validation (block-table snapshots, restart on any
rank count; XDMF is no longer written), CPU/GPU pressure consistency (the
standard suite is bit-exact CPU vs GPU incl. pn), cluster scaling/profiling (see
tutorials/turbulentBoundaryLayer/overheadTest/ results_horeka_*.md; the per-phase
timers are [output] profile = true), explicit halo-exchange/MPI-wait timers
(profiling.f90 exch_timing), and communication/computation overlap (measured
and closed; see CLAUDE.md "The 2:1 exchange at scale").

1. Portability of GPU builds.
   - The code assumes GPU-aware MPI for GPU builds and does not check for it.
   - If a system lacks CUDA-aware MPI, fail clearly or document the required
     module/runtime configuration. The working HoreKa build (incl. parallel
     HDF5, build_hdf5.sh) and launch scripts are in
     tutorials/turbulentBoundaryLayer/overheadTest/horeka/ but are not yet
     distilled into docs/installation.md.

2. Decomposition autotuning (outside the solver core).
   tools/moby_tune.sh already finds the rank-to-GPU mapping (MOBY_GPU_ORDER) by
   measurement. Not yet done: a harness that tunes the explicit decomposition
   the solver reads,

   [mpi]
   dims = nxr nyr nzr

   and a few launcher/MPI presets.
   - Try all reasonable factorizations of the rank count; order/prune with a
     surface-area model, choose by measurement.
   - Compare a small set of robust launcher options (--bind-to none/core,
     ppr:4:node, PE=1/2) and MPI presets via MPI_EXTRA_ARGS (default,
     --mca pml ucx, --mca pml ucx --mca coll_hcoll_enable 0). Avoid aggressive
     UCX_TLS settings unless the cluster documentation recommends them.
   - Workflow: generate candidates, run each 10-20 steps with output disabled,
     repeat 2-3 times, store seconds_per_step + dims + preset + flags + exit
     code, produce a sorted table.
   Guiding principle: autotune the scripts and input files, not the solver
   logic.
